## 0. 决策摘要

### 0.1 用户技术偏好

| 维度 | 用户偏好 | 分析 |
|------|----------|------|
| **后端语言** | **TypeScript** | 与前端共享类型、降低上下文切换 |
| **桌面框架** | **Electron** | 生态最成熟、Node.js 原生集成 |
| **构建工具** | **Vite** | 极速 HMR、现代打包 |
| **UI 框架** | **LobeHub 生态为主** | antd v6 + @lobehub/ui 全家桶 |
| **输入编辑器** | **@lobehub/editor** | AI 交互面板的富文本/指令输入编辑器 |
| **技术要求** | 最新稳定版本 | 生产级可靠性 |

### 0.2 与原设计文档的差异

| 维度 | 原设计 (v2.0) | 新方向 (v3.2) | 原因 |
|------|:---:|:---:|------|
| **桌面框架** | Tauri 2.x (Rust) | **Electron** | 用户偏好，Node.js 原生集成 |
| **核心引擎** | Rust | **TypeScript** | 用户偏好，团队技能匹配 |
| **前端框架** | React 18 | **React 19** | 升级到最新稳定版 |
| **构建工具** | Cargo + pnpm | **Vite + pnpm** | 统一构建链 |
| **UI 组件库** | shadcn/ui + Tailwind | **antd v6 + antd-style + @lobehub/ui** | LobeHub 生态，Chat/Markdown 开箱即用 |
| **AI 输入编辑器** | Monaco / 自建 | **@lobehub/editor** (Lexical) | AI 对话输入场景，支持富文本/指令/附件 |
| **代码编辑器** | CodeMirror 6 | **Monaco Editor** | IDE 级代码编辑能力 |

### 0.3 v3.2 关键变更说明（相对 v3.1）

> **重要变更**: 本版本相对 v3.1 的核心变化是 **将 @lobehub/editor 纳入核心接入**，定位为「AI 交互面板输入编辑器」，与 [09-LobeHub生态集成方案.md](./09-LobeHub生态集成方案.md) 中「❌ 不接入」的决策形成 **覆盖**。

| 变更点 | 09 文档原决策 | v3.2 实际决策 | 理由 |
|--------|:---:|:---:|------|
| **@lobehub/editor** | ❌ 不接入 | ✅ **核心接入** | 用户指定作为 AI 交互输入编辑器 |
| **应用定位** | AI 交互面板用 Monaco | Monaco 仅用于代码侧 | 区分「代码编辑」与「AI 对话输入」两类场景 |
| **布局形态** | 未明确 | 类 Codex/Claude/OpenCode App 的三栏 AI IDE 布局 | 对标主流 AI IDE 体验 |

**@lobehub/editor 接入理由（覆盖原决策）**：
1. **场景匹配**: @lobehub/editor 基于 Meta Lexical，擅长 WYSIWYG 富文本编辑，**与 AI 对话输入场景天然匹配**（支持 @提及、/命令、文件附件预览、Markdown 混排）
2. **职责分离**: 代码编辑用 Monaco（IDE 级），AI 对话输入用 LobeHub editor（富文本级），各司其职
3. **生态统一**: 与 @lobehub/ui 的 Chat 组件、Markdown 渲染形成完整闭环
4. **指令友好**: 富文本能力可让 `/命令`、`@文件`、`#智能体` 等以「芯片/胶囊」形式内联展示，体验优于纯文本输入
5. **附件渲染**: 文件附件、图片、代码片段可在输入框内直接渲染预览

## 2. 核心架构方案（三种方案对比）

### 2.1 方案 A：纯 TypeScript Monolith

```
┌──────────────────────────────────────────────┐
│                  Electron Main Process        │
│  ┌────────────────────────────────────────┐  │
│  │         Agent Engine (TS)               │  │
│  │  ┌──────┐ ┌──────┐ ┌──────┐ ┌───────┐ │  │
│  │  │ Loop │ │Tool  │ │MCP   │ │Prompt │ │  │
│  │  │Engine│ │System│ │Client│ │Engine │ │  │
│  │  └──────┘ └──────┘ └──────┘ └───────┘ │  │
│  │  ┌──────┐ ┌──────┐ ┌──────┐           │  │
│  │  │Context│ │Perm  │ │Config│           │  │
│  │  │Engine│ │Gateway│ │System│           │  │
│  │  └──────┘ └──────┘ └──────┘           │  │
│  └────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────┐  │
│  │         SQLite (better-sqlite3)         │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
         ↕ IPC (contextBridge)
┌──────────────────────────────────────────────┐
│              Electron Renderer Process        │
│  ┌────────────────────────────────────────┐  │
│  │   React 19 + Vite + @lobehub/ui (主) + antd (兜底) │
│  │  ┌────────┐ ┌────────┐ ┌────────────┐ │  │
│  │  │ Chat   │ │ Loop   │ │ Settings   │ │  │
│  │  │ Panel  │ │ Trace  │ │ Panel      │ │  │
│  │  └────────┘ └────────┘ └────────────┘ │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

**优点**：单一语言、调试简单、部署简单
**缺点**：主进程阻塞影响 UI、Agent 崩溃 = 整个应用崩溃、无法多核并行

**适用场景**：MVP 快速验证，小团队

**适用场景**：v1.0+ 企业版，团队协作

### 2.5 推荐方案

> **🏆 推荐方案 B：主进程 + Worker Threads**
>
> **MVP 阶段 (v0.1-v0.2)**: 方案 B，快速验证核心 Agent 能力
> **成长阶段 (v0.3-v0.9)**: 方案 B 优化，逐步抽取独立服务
> **企业版 (v1.0+)**: 迁移到方案 C，支持团队协作和远程部署
>
> **迁移路径**：方案 B 的 Worker 接口设计时预留 HTTP 适配层，可平滑迁移到方案 C

### 3.3 UI 组件优先级策略 (v3.3 新增)

> **关键决策**：遵循 [LobeHub 官方 React 组件编写指南](https://www.skills.sh/lobehub/lobehub/react)，**禁止将 antd v6 + antd-style 作为首选 UI 框架**。详见 [09 文档 v1.2 §0.4](./09-LobeHub生态集成方案.md)。

#### 3.3.1 组件优先级（5 级降序）

| 优先级 | 来源 | 说明 | 使用场景 |
|:---:|------|------|----------|
| **P1** | `src/components` | 项目自建可复用组件 | 项目特定 UI（如 AI 状态面板、Agent 模式切换器） |
| **P2** | `@lobehub/ui/base-ui` | **无头原语 (Headless Primitives)**，优先使用 | Overlay、Form、Navigation 等基础原语 |
| **P3** | `@lobehub/ui` | 高级组件（antd 包装层） | Chat/Markdown/Layout/DraggablePanel/ActionIcon 等 |
| **P4** | `antd v6` | **仅当 @lobehub/ui 完全无法满足时**（兜底） | 复杂 Table、Tree 等 @lobehub/ui 未覆盖组件 |
| **P5** | 自定义实现 | 真正的最后手段 | 特殊定制需求 |

> **重要规则**：如果组件存在于 `@lobehub/ui/base-ui`，**禁止**导入同名的根导出（`@lobehub/ui`）或 antd 原生 API。

#### 3.3.2 样式方案优先级（3 级降序）

| 优先级 | 方案 | 说明 | 使用场景 |
|:---:|------|------|----------|
| **S1** | `createStaticStyles` + `cssVar.*` | **零运行时**，模块级样式（首选） | 大多数样式场景 |
| **S2** | 内联 `style` 属性 | 简单一次性样式 | 快速原型、动态值少的场景 |
| **S3** | `createStyles` + `token` (antd-style) | **最后手段**，仅用于真正动态样式 | JS 颜色函数（readableColor/chroma）等 |

> **禁止**：直接调用 `antd-style` 的 `createTheme` API。主题通过 `@lobehub/ui` 的 `ThemeProvider` 注入。

#### 3.3.3 主题与布局策略

| 维度 | 方案 | 说明 |
|------|------|------|
| **主题** | `@lobehub/ui` ThemeProvider | 内部封装 antd ConfigProvider，支持 Light/Dark 自动切换 |

### 3.4 编辑器分工（关键决策）

> **设计决策 D3.1**: 代码编辑与 AI 对话输入采用 **双编辑器架构**，各司其职。

| 编辑器 | 用途 | 选型 | 理由 |
|--------|------|------|------|
| **代码编辑器** | 右侧资源管理器/文件预览/Diff 查看 | **Monaco Editor** (@monaco-editor/react) | IDE 级能力、语法高亮、多光标、LSP 集成 |
| **AI 输入编辑器** | 中间主交互区底部输入框 | **@lobehub/editor** (Lexical) | 富文本、/命令芯片、@文件提及、附件预览、Markdown 混排 |
| **终端** | 右侧终端面板 | **xterm.js** | Web 终端事实标准 |

**为何不用 Monaco 做 AI 输入？**
- Monaco 是纯代码编辑器，不支持富文本（粗体/列表/引用/图片内联）
- AI 输入场景需要 `@文件` 变成芯片、`/命令` 弹出菜单、附件以卡片展示——这些是富文本能力
- @lobehub/editor 基于 Lexical，可深度定制节点类型，完美适配「指令式 AI 输入」交互

### 4.3 Agent Loop 设计参考

> **重要：直接参考 OpenCode 的 Agent Loop 设计**
>
> OpenCode 的核心 Agentic Loop 设计非常优秀，我们应直接参考其架构：
>
> ```
> SessionPrompt.loop() {
>   while (finish === "tool-calls") {
>     1. 解析可用工具（按 Agent + Model 筛选）
>     2. 注入系统提醒
>     3. LLM.stream() 流式调用
>     4. 处理流事件（text-delta / reasoning-delta / tool-call）
>     5. 检查完成条件 → 无工具调用则结束
>   }
> }
> ```
>
> **我们可复用的设计模式**：
> - Tool 的 lazy 初始化模式（`Tool.Info<Params>`）
> - 模型感知的工具筛选（GPT → apply_patch, Claude → edit）
> - 9 层容错编辑匹配策略
> - Doom Loop 检测（连续 3 次相同调用触发警告）
> - 消息压缩（Compaction Agent）

### 4.4 关键设计决策

| 决策 | 方案 | 理由 |
|------|------|------|
| Agent Loop | 单循环 + 子循环 | 参考 OpenCode，复杂任务用 task 工具委派 |
| 工具执行 | Worker Thread 隔离 | 崩溃不影响主循环 |
| 模型抽象 | Provider Adapter 模式 | 支持 Anthropic/OpenAI/Ollama/兼容接口 |
| 提示词管理 | 七层洋葱模型 | 继承原设计文档 |
| 权限控制 | 规则引擎 | 参考 OpenCode 的分层规则 + BashArity |

4. **右侧功能面板 (Right Panel)** — 右侧，可折叠，多 Tab 切换
5. **上下文状态栏 (Context Status Bar)** — 主交互区顶部

### 11.2 头部窗口栏 (Title Bar)

#### 11.2.1 布局

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ ┌──────┐┌───┐┌──────────────────────────────────────────┐┌─────────────────────────────┐│
```

#### 11.2.2 区域功能

| 子区域 | 元素 | 功能 | 交互 |
|--------|------|------|------|
| **左侧区** | Logo | 品牌标识，点击回到主页/欢迎页 | 单击 |
| | ☰ (折叠按钮) | 折叠/展开左侧导航栏 | 单击切换，状态持久化 |
| **中间会话信息区** | 会话标题 | 显示当前会话名称（可编辑） | 双击重命名 |
| | 📁 工作文件夹 | 显示当前打开的项目路径 | 单击下拉切换最近项目 |
| | 🌿 分支 | 显示当前 Git 分支名 | 单击切换分支/新建分支 |
| **右侧外部工具区** | 📂 资源管理器 | 在系统资源管理器中打开工作目录 | 单击调用 `shell.openPath` |
| | 📝 VSCode | 在 VSCode 中打开当前项目 | 单击调用 `shell.openExternal` |
| | 🐘 JetBrains | 在 IntelliJ/PyCharm 中打开 | 单击调用对应 IDE CLI |
| | 💻 Terminal | 在系统终端中打开工作目录 | 单击调用 `shell.openTerminal` |
| **窗口控制** | ─ □ ✕ | 最小化/最大化/关闭 | 标准 Electron |

#### 11.2.3 设计目标

1. **无边框窗口**: 使用 Electron `frame: false` + 自定义 TitleBar，统一跨平台体验

1. **指令式输入**: `/命令`、`@文件`、`#智能体` 以芯片形式内联，所见即所得
2. **富文本能力**: 区别于纯文本输入框，支持格式化与附件
3. **模式感知**: Agent 模式切换改变发送行为（plan 模式先确认计划）
4. **多模态**: 支持文本/图片/文件/代码片段混合输入
5. **快捷高效**: 全键盘操作，鼠标可选

- 点击 [发送] 或 Enter → 调用 `agent.sendMessage({ content, mode, model, attachments, mentions })` →
  - 主交互区追加 User ChatItem + 创建 Assistant ChatItem (loading 态)
  - 上下文状态栏更新 Token 占用
  - 右侧状态面板开始显示 Loop 进度
- Shift+Enter → 换行
- ESC → 清空编辑器 / 取消正在输入的命令

#### 11.7.5 设计目标

1. **状态全景**: AI 交互期间的所有状态（上下文/Todo/计划/工具/Skill/MCP/成本）集中可视
2. **双向联动**: 状态变化实时反映到面板，面板操作反向影响 Agent
3. **变更可控**: Diff 面板让用户决定保留/撤销，体现「Loop 可干预」
4. **外部工具集成**: 终端/浏览器内嵌，无需切换应用

#### 11.7.6 交互联动

- 点击顶部 💻 终端 → 面板底部展开终端区（xterm.js），支持多标签
- 点击顶部 🌐 浏览器 → 面板切换为 BrowserView，可输入 URL 或预览本地 dev server
- 点击 ⇆ 折叠 → 右侧面板隐藏，主交互区扩展
- 切换 Tab → 内容区切换，状态保持
- 资源管理器双击文件 → 调用 `shell.openInIDE(path)`
- Diff Tab 点击「保留」→ 调用 `tool.applyChange(fileId)` → 文件写入
- Diff Tab 点击「撤销」→ 调用 `tool.revertChange(fileId)` → 文件回退
- 源代码管理「提交」→ 调用 `git.commit(message, files)` → 刷新状态
- AI 状态监控点击工具调用项 → 主交互区定位到对应消息
- AI 状态监控点击 MCP 失败项的「重连」→ 调用 `mcp.reconnect(name)`

### 11.10 主题与四色同步 (v3.3 修订)

基于 [09-LobeHub生态集成方案.md 附录 B](./09-LobeHub生态集成方案.md)，实现 UI / Monaco / LobeEditor / 终端四色同步。

> **v3.3 修订**：UI 层主题通过 `@lobehub/ui` ThemeProvider 注入，**禁止**直接调用 `antd-style` `createTheme` API。

```typescript
// 通过 @lobehub/ui ThemeProvider 注入主题 (v3.3 推荐方式)
import { ThemeProvider } from '@lobehub/ui';

<App>
  <ThemeProvider themeMode="dark" customToken={{ /* 自定义 token */ }}>
    {/* 子组件 */}
  </ThemeProvider>
</App>

// 或获取主题 token 用于四色同步
import { useToken } from '@lobehub/ui';
const { token } = useToken(); // antd Tokens

// Monaco Editor 主题同步 (代码编辑器)
function syncMonacoTheme(antdTokens: ThemeToken) {
  monaco.editor.defineTheme('openwork-theme', {
    base: 'vs-dark',
    inherit: true,
    colors: {
      'editor.background': antdTokens.colorBgContainer,
      'editor.foreground': antdTokens.colorText,
    },
    rules: [/* ... */],
  });
}

// @lobehub/editor 主题同步 (AI 输入编辑器)
function syncLobeEditorTheme(antdTokens: ThemeToken) {
  // Lexical 编辑器主题通过 CSS 变量注入
}

// xterm.js 终端主题同步
function syncTerminalTheme(antdTokens: ThemeToken) {
  const terminalTheme: ITheme = {
    background: antdTokens.colorBgElevated,
    foreground: antdTokens.colorText,
    cursor: antdTokens.colorPrimary,
  };
}
```

主题切换时，四个层（antd UI / Monaco / LobeHub editor / xterm）同步刷新，确保视觉一致。
