## 1. 产品定位与核心价值

### 1.1 一句话定位

**OpenCoding** 是一款开源、本地优先、高度可配置的多客户端 Coding Agent 平台，由 headless 后端引擎 + 多种客户端（Desktop / TUI / Web / CLI）组成，它不只是"Chat + 代码补全"，而是一个具备**全生命周期感知-规划-执行-反思-记忆**能力的自主编码智能体。用户可使用官方 Desktop / TUI / Web / CLI 客户端，也可基于公开契约自行开发定制客户端。

> **v0.1 阶段性说明** (v2.3 新增): 多客户端平台是产品的**长期愿景**，但 v0.1 优先交付 Desktop 客户端 (嵌入式模式)，TUI / Web / CLI / 自定义客户端 SDK 规划于 v0.2+，服务式 (Service) 后端、Sub-Agent、Multi-Agent 等多客户端相关能力推迟到 v0.2~v0.3。这一收缩策略参照 07-多角色审视评估报告 §1.1 (S1) 与 §8.3 总体结论，使 v0.1 在 6-8 周内可交付，同时保留 v4.1 前后端分离架构的演进余地。

### 1.2 核心差异化卖点 (一句话版)

> **"看得见、管得住、带得走"的 Coding Agent**
> — 全链路可观测 (Harness Debugger) × 全过程可干预 (动态结果调整) × 全数据可迁移 (Profile + 数据库导出)

### 1.3 六大核心支柱

| # | 支柱 | 一句话说明 | v0.1 聚焦 |
|---|------|-----------|:---:|
| 1 | **Agent 原生** | 内置 PAOR (Perceive-Act-Observe-Reflect) 完整循环，而非简单工具调用 | ✅ v0.1 |
| 2 | **全链路可观测** | 提示词、上下文、工具调用、Loop 状态每一步都可查看、可回放、可调试 | ✅ v0.1 |
| 3 | **全过程可干预** | 任何时候都可修改对话/工具结果/Agent 决策，动态调整而非打断重来 | ✅ v0.1 |
| 4 | **配置即产品** | 所有变量、参数通过声明式配置对外暴露，用户可高度自定义 | 🟡 v0.2+ |
| 5 | **全生命周期扩展** | Hooks / 插件 / MCP / Skills / Sub-Agent 五条等价扩展通道 | 🟡 v0.2+ |
| 6 | **数据主权** | 本地 SQLite 存储一切，一键导出迁移，端到端加密可选云同步 | ✅ v0.1 |

> **v0.1 聚焦说明** (v2.3 新增): v0.1 聚焦核心 Agent 循环 (PAOR) 与可观测性 + 可干预性 + 数据主权，共 4 个支柱优先交付；扩展生态 (全生命周期扩展) 与高度配置化 (配置即产品) 在 v0.2+ 逐步交付。这一聚焦策略参照 07-多角色审视评估报告 §1.4 (M2)，避免 v0.1 陷入"广度优先、深度不足"，确保核心 Agent 体验在 6-8 周内达到可用水平。

### 1.4 商业模式与开源策略

#### 1.4.1 开源策略

**核心定位**: Open Source + Cloud Services（类似 GitLab/Supabase 模式）

```
开源核心 (MIT License)
├── Agent 引擎 (TypeScript, headless @opencode/core)
├── 多客户端 (Desktop/TUI/Web/CLI)
├── 插件 SDK
├── 内置 Skills & MCP Server
└── SQLite 持久化层

企业增值 (Pro License / SaaS)
├── 企业管理控制台 (Web Dashboard)
├── SSO / OIDC / LDAP 集成
├── 审计日志中心化收集
├── 团队 Profile 模板库
├── 私有模型网关 (集中管理 API Key)
├── 优先技术支持 SLA
└── 安全合规认证 (SOC 2 / ISO 27001)
```

#### 1.4.2 收入模型

| 层级 | 定价模式 | 目标用户 | 预估 ARPU |
|------|----------|----------|:---:|
| **Community** | 免费 + 自带 Key | 个人开发者 | $0 |
| **Pro** | $15/月 或 $144/年 | 专业开发者 | $120/年 |
| **Team** | $30/人/月 | 中小团队 (2-50人) | $250/人/年 |
| **Enterprise** | 定制报价 | 大型企业 (50+人) | $500+/人/年 |

#### 1.4.3 护城河分析

| 护城河 | 说明 | 持续性 |
|--------|------|:---:|
| **数据网络效应** | 用户越多 → Skills/Hooks/Profile 越多 → 产品越好 | 中 |
| **切换成本** | SQLite 全量持久化 → 用户数据积累 → 迁移困难 | 高 |
| **生态锁定** | 插件市场 + MCP Server 生态 + 社区 Skills | 中高 |
| **技术壁垒** | TypeScript 全栈 + PAOR 循环 + 全链路可观测 + 前后端分离多客户端架构 | 中 |
| **开源品牌** | 开发者信任 + 社区贡献飞轮 | 高 |

### 1.5 从竞品迁移指南

#### 1.5.1 Claude Code 用户为什么应该迁移？

| Claude Code 痛点 | 本产品解决方案 |
|------------------|---------------|
| ❌ 闭源，不可定制核心行为 | ✅ MIT 开源，全量配置暴露 |
| ❌ 提示词黑盒，无法查看/修改 | ✅ 七层洋葱 Prompt 完全透明可编辑 |
| ❌ 无插件/Hooks 系统 | ✅ 全生命周期 Hooks + 沙箱插件 |

| ❌ 无 Profile 切换 | ✅ 多 Profile 一键切换 |
| ❌ 无法动态调整中间结果 | ✅ 核心能力：任意步编辑/回退/分支 |

#### 1.5.2 Cursor 用户为什么应该迁移？

| Cursor 痛点 | 本产品解决方案 |
|------------|---------------|
| ❌ 闭源，订阅制锁死 | ✅ 开源免费，自带 Key |
| ❌ Agent 能力弱（主要是补全） | ✅ 完整 PAOR 循环 Agent |
| ❌ 无 MCP 支持 | ✅ MCP 一等公民 |
| ❌ 无 Sub-Agent 并行 | ✅ 多 Agent 并行协作 |
| ❌ 无数据导出 | ✅ 全量数据可迁移 |

#### 1.5.3 迁移路径

```
1. 安装 OpenCoding Desktop
2. 使用导入功能：
   - 导入 Claude Code 的 CLAUDE.md → 自动转为 Profile
   - 导入 Cursor 的 .cursorrules → 自动转为项目配置
   - 导入 MCP 配置 (Claude Desktop / Cursor / Cline 格式)
3. 选择"Claude Code 兼容" Persona（保留熟悉的交互风格）
4. 开始使用，逐步探索差异化功能
```

## 4. 功能模块详解

### 4.1 Agent 核心引擎

#### 4.1.1 PAOR 循环 (Perceive-Act-Observe-Reflect)

| 功能点 | 说明 | 对标来源 |
|--------|------|----------|
| **Perceive (感知)** | 整合上下文: 文件/Git/诊断/选区/历史 | Claude Code Context |
| **Act (行动)** | LLM 决策并调用工具 (内置/MCP/插件/Skill) | Codex CLI Tool Use |
| **Observe (观察)** | 结构化解析工具输出，写入工作记忆 | OpenCode Observation |
| **Reflect (反思)** | 每 N 轮自评进度，必要时重规划 | 自研增强 |

#### 4.1.2 子循环系统

| 子循环 | 触发条件 | 功能 |
|--------|----------|------|
| **Planning Loop** | 预计步数 > 阈值 | 先产出计划 DAG，用户审批后执行 |
| **Execution Loop** | Plan 中的子任务 | 串行/并行执行，依赖拓扑排序 |
| **Verification Loop** | 代码改动后 | 自动跑测试/Lint/类型检查 |
| **Reflection Loop** | 每 N 轮或阶段完成 | 自评进度，判断是否走偏 |
| **Recovery Loop** | 工具失败/测试失败 | 分析错误，自动修复，最多 K 次 |

#### 4.1.3 任务编排 (Task Orchestration)

- 任务分解为 DAG (有向无环图)，含依赖关系
- 无依赖子任务可并行派发给 Sub-Agent
- 进度可视化: 任务树 + 当前节点 + 阻塞原因
- 结果聚合: 合并/取最新/人工裁决

#### 4.1.4 循环控制与干预

| 功能 | 说明 |
|------|------|
| 终止条件 | 任务完成/最大迭代/用户停止/成本超限/不可恢复错误 |
| 暂停与恢复 | 任意点暂停，保存 Loop 状态，从 checkpoint 恢复 |
| 时间旅行 | 回退到历史某步重放 (非确定性标注) |
| HITL 干预点 | 每步确认/关键节点确认/全自动 三档 |
| 干预动作 | 批准/修改/拒绝/接管 (用户手动执行) |

#### 4.1.5 多 Agent 协作 (Multi-Agent)

- **主从模式**: 主 Agent 派生 Sub-Agent 处理子任务
- **并行模式**: 多个 Sub-Agent 并行处理独立子任务
- **专家模式**: 不同 Sub-Agent 装载不同 Persona/Skills
- **上下文隔离**: Sub-Agent 不直接共享上下文
- **成本归属**: Sub-Agent 成本归属到父任务

### 4.2 上下文与知识管理

#### 4.2.1 上下文来源 (9 类)

| 来源 | 采集方式 | 典型场景 |
|------|----------|----------|
| **显式上下文** | 用户选中/ @文件/ @符号 | 精确指定修改范围 |
| **文件上下文** | 当前文件 + 相关文件 | 跨文件关联修改 |
| **代码库索引** | Tree-sitter 符号 + 依赖图 | 全局符号跳转与关联 |
| **Git 上下文** | diff/log/branch/blame | 理解变更历史 |
| **终端上下文** | 最近命令与输出 | 调试/运行结果感知 |
| **编辑器上下文** | 光标/诊断/折叠区 | 当前编辑焦点 |
| **浏览器上下文** | 文档页/控制台 (可选) | Web 开发调试 |
| **项目配置** | package.json/tsconfig 等 | 项目技术栈感知 |
| **会话历史** | 当前 + 跨会话记忆 | 上下文延续 |

#### 4.2.2 上下文压缩

| 策略 | 说明 |
|------|------|
| **分层摘要** | 近因窗口(原样) → 摘要窗口(压缩) → 事实窗口(结构化 KV) |
| **Token 预算管理** | 全局预算 = 模型窗口 - 输出预留 - 工具预留 - 动态预留 |
| **压缩策略** | compress-dynamic / truncate-tail / summarize-all / drop-low-weight |
| **代码指纹** | 已读文件 hash + 摘要，避免重复读全文 |
| **重要度排序** | 相关性(向量) × 时效性 × 用户标记 |

#### 4.2.3 上下文检索 (Hybrid RAG)

- **语义检索**: 向量 (sqlite-vec / LanceDB / Qdrant)
- **关键词检索**: BM25 / FTS5
- **结构检索**: 符号图 / 引用图 / 调用链
- **混合排序**: RRF (Reciprocal Rank Fusion) 融合多路结果
- **触发方式**: 显式 (@symbol) + 隐式 (LLM 主动调用)

#### 4.2.4 上下文窗口管理

- 优先级队列: 按重要度入队，LRU + 重要度驱逐
- 钉选 (Pin): 用户可钉选文件不被驱逐
- 驱逐日志: 被丢弃内容可找回
- 动态窗口: 简单查询小窗口，复杂重构大窗口

#### 4.2.5 记忆系统 (Memory)

| 级别 | 范围 | 生命周期 | 示例 |
|------|------|----------|------|
| **工作记忆** | 当前会话 | 会话结束 (可存档) | 当前任务上下文 |
| **项目记忆** | 当前项目 | 持久 | 项目约定/决策/教训 |
| **全局记忆** | 跨项目 | 持久 | 用户偏好/通用经验 |

- 记忆写入: Agent 主动调用 `memory_write` 工具，或 Hooks 自动提取
- 记忆分类: decision / fact / preference / lesson / todo
- 记忆可搜索、可编辑、可遗忘

#### 4.3.3 权限分级

| 级别 | 行为 | 默认策略 | 示例 |
|:----:|------|----------|------|
| L0 | 只读 | 自动允许 | read/grep/glob |
| L1 | 变更 | 可配置 | write/edit |
| L2 | 破坏性 | 需确认 | delete/run_command |
| L3 | 关键 | 永远需确认+不可擦除审计 | rm -rf/sudo/force push |

#### 4.3.4 确认机制

- 一次性批准 / 本会话批准 / 本项目批准 / 永久批准

- 审批缓存减少重复确认

#### 4.3.5 AI Provider 注册与抽象接入 (v2.4 新增)

> **目标**: 实现对业界全部主流 LLM Provider 的"全兼容抽象接入"，并允许用户/企业通过 SDK 自定义接入私有模型网关，做到一行注册、能力自描述、统一调用。

**核心机制**:

| 机制 | 说明 |
|------|------|
| **Provider Registry (注册表)** | 所有 Provider 在统一注册表中登记，外部工具通过 `@opencode/ai-sdk` 的 `registerProvider(adapter)` 注入；启动时按配置加载，支持热插拔 |
| **Adapter 契约** | 统一 `AIProviderAdapter` 接口: `chat() / stream() / countTokens() / tools() / capabilities()`；Adapter 负责屏蔽流式协议、工具调用协议、系统消息位置、stop 序列差异 |
| **能力自描述 (Capabilities)** | 每个 Adapter 声明能力位: `streaming / tool_call / vision / json_mode / parallel_tool / prompt_caching / thinking / system_as_role`；引擎按能力位降级处理，缺失能力走 polyfill |
| **AuthProvider (鉴权抽象)** | 密钥经 OS Keychain 抽取，注入到 Adapter；支持环境变量/配置项/Keychain 三种来源；企业网关支持借用 refresh token |
| **路由与 Fallback** | Router 按任务类型/成本/延迟/能力位自动选 Provider；主 Provider 失败沿 fallback 链降级；本地 Ollama 作为兜底底线 |
| **统一计价表** | 内置主流模型 $/Mtok 单价表；自定义 Provider 可声明计价函数；成本归因到调用 |

**内置 Provider (基线)**:

| 类别 | Provider | v0.1 |
|------|----------|:---:|
| 商业 API | OpenAI / Anthropic / Google (Gemini) / Azure OpenAI / AWS Bedrock / Mistral / Cohere / DeepSeek / xAI Grok | v0.1 仅 OpenAI/Anthropic/Google + 任意 OpenAI 兼容；其余 v0.2+ |
| OpenAI 兼容网关 | OpenRouter / Together / Fireworks / 自建兼容端点 | v0.1 "任意 OpenAI 兼容" 子集 |
| 本地推理 | Ollama / llama.cpp / vLLM / LM Studio | v0.1 Ollama；其余 v0.2+ |
| 企业网关 | 自定义 (经 Adapter SDK 注入) | v0.5 |

**自定义接入**: 用户/企业可编写 Adapter npm 包，经 Plugin 系统注册到 Registry，享受与内置 Provider 同一的调用/计费/审计/Fallback 待遇，实现"全部兼容抽象接入"。

### 4.14 定时任务与调度系统 (v2.4 新增)

> **差异化能力**: 业界 Coding Agent 多为"请求-响应"模式，缺少持续运营能力。本产品提供内置调度器，让 Agent 可以周期性、条件性地自主运行，覆盖"夜间巡检 / 定时重构 / 代码看护 / 报告生成"等自动化场景。

**调度形态**:

| 形态 | 说明 | 触发方式 | 示例 |
|------|------|----------|------|
| **定时 (cron)** | 按 cron 表达式周期触发 | `cron("0 2 * * 6")` | 每周六凌晨 2 点运行全项目 Lint+测试 |
| **间隔 (interval)** | 按固定时间间隔触发 | `interval(3600s)` | 每小时检查依赖安全告警 |
| **事件 (event)** | 由事件触发 | `on_commit` / `on_idle` / `on_cost_warn` | commit 后自动运行审查 |
| **一次性 (once)** | 延迟到指定时刻运行一次 | `at("2026-08-01T10:00")` | 在发布窗口生成发版说明 |

**任务定义要素**:
- 任务名称 / 描述 / 启用开关
- 调度表达式 (cron / interval / event / once)
- 绑定 Persona + Skills + MCP 子集 (复用 Profile 体系)
- IO 模式: `silent`(静默执行, 仅产日志) / `notify`(完成后通知) / `interactive`(到期弹窗交互)
- 预算上限 (独立于主会话预算)
- 权限策略 (默认收紧到只读，破坏性操作需预审批准)
- 失败策略: retry / skip / escalate(通知人工) / halt
- 持久化: `scheduled_tasks` 表 (定义) + `scheduled_task_runs` (执行日志)

**安全约束 (关键澄清)**:
- 定时任务默认在只读权限下运行；任何写/命令操作须在任务定义中显式声明并预先审批
- 强制 dry-run 预演一次后才能启用周期性破坏性任务
- 定时任务调用全量记入审计日志（与手工调用同一审计通道）
- 全局并发上限 + 单任务速率限制，避免失控

**可观测**: 调度日历视图 / 运行历史时间线 / 下次执行预测 / 失败告警通知。

### 4.15 目标管理 (Goal System) (v2.4 新增)

> **定位**: 区别于"一次性任务"，目标是**中长期的、跨会话延续的、带达成判定**的意图载体。Planning Loop 产出的一次性 DAG 是目标的执行实例；Goal 系统管理目标本身的生命周期。

**Goal 实体结构**:
| 字段 | 说明 |
|------|------|
| 标题 / 描述 | 自然语言意图 |
| 验收标准 (AC) | 可机器/人工判定的达成条件清单 |
| 优先级 / 状态 | backlog / active / blocked / done / abandoned |
| 父子关系 | 支持 OKR 式分解 (目标→关键结果→子目标) |
| 关联实体 | 关联会话 / 记忆 / 定时任务 / GitHub Issue |
| 时间窗 | 起止时间 / deadline / 软逾期 |
| 进度度量 | 子任务完成率 / 验收项达成率 / 自动评估分数 |
| 上下文锚点 | 跨会话恢复时拉回的"工作上下文快照" |

**能力集**:
- **目标分解**: Agent `goal_decompose` 工具将自然语言目标拆为子目标 + 验收标准
- **跨会话续作**: 重启应用/新开一个会话时，Agent 自动 resume活跃 goal 的上下文
- **进度自评**: Reflect Loop 周期性对照验收标准自评进度，更新 goal 状态
- **障碍升级**: 连续 K 次自评无进展 → 升级为人工介入 + 通知
- **目标与任务联动**: Planning Loop 生成的 DAG 自动归属到当前活跃 goal
- **里程碑与回滚**: 关键节点为里程碑，可回溯某 goal 的全部会话与变更

### 4.16 提示词管理系统 (Prompt Management) (v2.4 新增)

> **定位**: §4.10.2 Prompt Inspector 解决"看"，本模块解决"管"——从只读检查升级为完整的版本化、可复用、可视化、可分享的提示词工程平台。

**分层体系 (七层洋葱模型已在 §4.10.2 定义)**:
system_meta → system_persona → system_policy → context_block → tool_manifest → user_message → memory_block

**提示词管理能力**:

| 能力 | 说明 |
|------|------|
| **模板库** | `prompt_templates` 表持久化命名模板；模板支持变量插值 `{{var}}` 与条件块 `{{#if}}` |
| **七层独立编辑** | 每一层可单独编辑、单独版本化、单独对比；保留默认层并支持 Layer override |
| **版本化** | 每次修改生成版本快照，可 diff / 回滚 / 标记 released |
| **模型适配** | 同一模板可声明多模型变体 (Anthropic system-as-role / OpenAI system message / 本地模型限制)，按 Provider 自动选择 |
| **A/B 实验** | 两个模板版本按比例分流，对比成功率/成本/满意度 (接 §4.13 A/B 框架) |
| **调试器** | Prompt Playground: 选模板→注入变量→离线调用模型→对比输出，不触发真实 Loop |
| **差异分析** | 前后两次推理的 actually-rendered prompt diff 视图 |
| **作用域** | 模板作用域: global / project / persona / session；优先级叠加 |
| **复用与分享** | 模板导出为 YAML / 包；社区模板导入；团队 Profile 内置模板集 |
| **审计与合规** | 模板变更有审计记录；企业可锁定某些层为只读 (合规要求) |

**内置模板 (种子集)**:
- planning_prompt / reflect_prompt / recovery_prompt / summarize_prompt / commit_msg_prompt / pr_desc_prompt / code_review_prompt / debug_diagnose_prompt / tdd_cycle_prompt / migration_plan_prompt (随 Skills v1 一起交付)
