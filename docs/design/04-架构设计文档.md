## 1. 架构概述

### 1.1 架构设计原则

| 原则 | 说明 |
|------|------|
| **核心 Rust, 扩展 JS** | 性能敏感的 Agent 核心引擎用 Rust 实现；插件生态与 UI 用 TypeScript |
| **进程隔离** | Agent/工具/插件/索引各自独立进程，崩溃不相互影响 |
| **事件驱动** | 所有模块通过统一 Event Bus 通信，解耦 + 可观测 |
| **配置驱动** | 所有行为参数通过配置控制，代码不硬编码业务逻辑 |
| **本地优先** | SQLite 全量持久化，离线可用，可选云同步 |
| **安全第一** | 权限网关 + 沙箱执行 + 审计日志，安全不可妥协 |

## 2. 分层架构设计

### 2.1 层间依赖规则

```
表现层 ──► 应用服务层 ──► Agent 核心层 ──► 能力扩展层
                                                    │
                                             模型抽象层
                                                    │
                                             基础设施层

规则:
1. 只能上层依赖下层，禁止反向依赖
2. 同层模块通过 Event Bus 通信 (解耦)
3. 基础设施层被所有层依赖 (工具性质)
```

### 2.2 各层职责

| 层 | 职责 | 关键技术 | 语言 |
|----|------|----------|:---:|
| **表现层** | UI 渲染、用户交互、通知 | Tauri + React + Tailwind | TS/JS |
| **应用服务层** | 会话管理、任务编排、权限仲裁、配置热加载 | Rust 核心 + IPC Bridge | Rust + TS |
| **Agent 核心层** | PAOR 循环、提示词组装、上下文管理、工具调度 | Rust | Rust |
| **能力扩展层** | 工具注册/MCP Client/插件沙箱/编辑器桥接 | Rust + Node Worker | Rust + TS |
| **模型抽象层** | 多 Provider 适配、路由、Fallback、成本控制 | Rust | Rust |
| **基础设施层** | 持久化、索引、加密、IPC、日志、更新 | Rust | Rust |

### 3.2 进程职责与隔离级别

| 进程 | 职责 | 隔离级别 | 崩溃影响 | 重启策略 |
|------|------|:---:|----------|----------|
| **Main** | UI 渲染、IPC 路由、生命周期管理 | 主域 | 整个应用退出 | 系统级恢复 |
| **Agent Worker** | LLM 推理、Loop 执行、上下文组装 | 沙箱 (无 FS 直接访问) | 当前会话中断 | 自动重启 + 会话恢复 |
| **Tool Worker** | 文件/终端/浏览器操作 | 沙箱 (白名单路径) | 当前工具调用失败 | 自动重启 |
| **Indexer Worker** | 代码库索引、向量计算 | 后台 (节流) | 索引暂停 | 自动重启 + 增量恢复 |
| **Plugin Worker** | 第三方插件运行 | 强沙箱 (权限受限) | 插件不可用 | 按需重启 |
| **MCP Server** | MCP 工具提供 | 外部进程 | 该 MCP 工具不可用 | 自动重连 |

### 3.2.1 故障恢复 SLA

| 故障场景 | 检测方式 | 恢复策略 | 最大数据丢失 | 恢复时间 |
|----------|----------|----------|:---:|:---:|
| **Agent Worker 崩溃** | 进程退出信号 + 心跳超时 (5s) | 从最近检查点恢复，重新组装上下文后继续 | 最近检查点之后的所有步骤 (最坏 ~3 轮) | < 10s |
| **Tool Worker 崩溃** | 进程退出信号 + 工具调用超时 (30s) | 工具调用标记失败，返回结构化错误给 Agent Worker；Agent 决定重试/跳过 | 当前工具调用结果 | < 5s |
| **Indexer Worker 崩溃** | 进程退出信号 + 心跳超时 (15s) | 自动重启 + 从 index_meta 恢复增量索引进度 | 当前正在索引的文件 | < 20s |
| **Plugin Worker 崩溃** | 进程退出信号 | 隔离，标记插件状态为 error，不影响主循环 | 插件贡献的功能 | 手动重启用 |
| **MCP Server 崩溃** | 进程退出 + 健康检查失败 | 工具标记为不可用，自动重连 (指数退避: 1s/2s/4s/8s/30s) | 该 MCP 提供的工具 | 取决于 MCP Server 启动速度 |
| **SQLite 写入失败** | SQLite 返回错误码 | 重试 3 次 (间隔 100ms/200ms/400ms)，仍失败则降级到只读模式 + 告警 | 最近一次未落盘的写入 | N/A (降级) |
| **LLM API 超时** | HTTP 超时 (可配置 60-300s) | Fallback 到备选 Provider 链；token 已消耗但不影响状态机 | 本次请求消耗的 token | 自动切换 |

### 3.2.2 Agent Worker 崩溃恢复状态机

```
                    ┌─────────────┐
                    │   RUNNING   │
                    └──────┬──────┘
                           │ crash detected (signal/heartbeat)
                           ▼
                    ┌─────────────┐
                    │ CRASHED     │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            ▼            ▼
    ┌──────────────┐ ┌──────────┐ ┌──────────────┐
    │ checkpoint   │ │ no       │ │ unrecoverable│
    │ exists       │ │ checkpoint│ │ error        │
    └──────┬───────┘ └────┬─────┘ └──────┬───────┘
           │              │              │
           ▼              ▼              ▼
    ┌──────────────┐ ┌──────────┐ ┌──────────────┐
    │ RESTORE      │ │ RESTART  │ │ TERMINATED   │
    │ (恢复上下文, │ │ (全新开始,│ │ (会话标记为  │
    │  继续循环)   │ │  通知用户│ │  不可恢复)   │
    └──────┬───────┘ │ 选择)    │ └──────────────┘
           │         └────┬─────┘
           │              │
           └──────┬───────┘
                  │
                  ▼
           ┌─────────────┐
           │   RUNNING   │ (恢复后继续)
           └─────────────┘
```

- **检查点频率**: 每轮 PAOR 循环完成后自动保存 (可配置为每 N 轮)
- **Token 处理**: 崩溃时已消耗但未完成推理的 token 记录在 model_calls 表中，标注 status='interrupted'
- **恢复后处理**: 从检查点恢复后，重新发送最近一次 LLM 请求 (包含完整上下文快照)

**Loop Engine 核心接口**:

```rust
/// Agent 引擎主接口
#[async_trait]
pub trait LoopEngine: Send + Sync {
    /// 启动 Agent 循环
    async fn run(&self, input: TaskInput) -> Result<SessionResult, LoopError>;

    /// 暂停循环 (返回检查点)
    async fn pause(&self) -> Result<Checkpoint, LoopError>;

    /// 从检查点恢复
    async fn resume(&self, checkpoint: Checkpoint) -> Result<SessionResult, LoopError>;

    /// 单步执行 (调试用)
    async fn step(&self) -> Result<StepResult, LoopError>;

    /// 获取当前 Agent 状态
    fn state(&self) -> AgentState;

    /// 订阅事件流
    fn events(&self) -> BroadcastReceiver<AgentEvent>;
}

/// Agent 状态
pub struct AgentState {
    pub session_id: String,
    pub loop_status: LoopStatus,    // idle | running | paused | completed | error
    pub current_step: u32,
    pub current_phase: LoopPhase,   // perceive | act | observe | reflect
    pub tokens_used: TokenUsage,
    pub cost_usd: f64,
    pub sub_agents_active: u32,
    pub pending_tool_calls: Vec<ToolCallId>,
}

/// 检查点 (完整 Loop 状态快照)
pub struct Checkpoint {
    pub id: String,
    pub session_id: String,
    pub step: u32,
    pub phase: LoopPhase,
    pub message_history: Vec<Message>,
    pub working_memory: HashMap<String, Value>,
    pub task_plan: Option<TaskPlan>,
    pub token_usage: TokenUsage,
    pub cost_usd: f64,
    pub created_at: i64,
}
```

**Prompt 组装流程**:

```rust
pub struct PromptAssembler {
    layer_manager: LayerManager,
    template_engine: TemplateEngine,
    model_adapter: ModelAdapter,
    budget_manager: TokenBudgetManager,
}

impl PromptAssembler {
    pub async fn assemble(&self, ctx: &AssemblyContext) -> Result<Prompt, PromptError> {
        // 1. 按层级收集 prompt 片段
        let mut layers = Vec::new();
        layers.push(self.layer_manager.build_l1(&ctx)?);  // Base Identity
        layers.push(self.layer_manager.build_l2(&ctx)?);  // Persona
        layers.push(self.layer_manager.build_l3(&ctx)?);  // Capabilities
        layers.push(self.layer_manager.build_l4(&ctx)?);  // Constraints
        layers.push(self.layer_manager.build_l5(&ctx)?);  // Task Template
        layers.push(self.layer_manager.build_l6(&ctx)?);  // Dynamic Context
        layers.push(self.layer_manager.build_l7(&ctx)?);  // User Override

        // 2. 合并层级 (后者覆盖前者)
        let merged = self.layer_manager.merge(layers);

        // 3. 模型适配 (格式转换)
        let adapted = self.model_adapter.adapt(merged, &ctx.model_info);

        // 4. Token 预算检查与压缩
        let final_prompt = self.budget_manager.fit(adapted, &ctx.budget_config)?;

        Ok(final_prompt)
    }
}
```

**索引增量更新算法**:

```
1. File Watcher 收到文件变更事件 (debounce 500ms)
2. 检查文件是否在 .gitignore / index.ignore 中 → 是则跳过
3. 读取文件内容 → 与缓存对比
   - 新增: 完整索引流程 (parse → chunk → embed → store)
   - 修改: 删除旧索引 + 完整索引新内容
   - 删除: 删除所有相关索引条目
4. 更新 index_meta 表 (记录最后索引时间和文件 hash)
5. 批量提交 (每 50 个文件或每 10 秒)
```

## 6. 事件系统设计

### 6.1 Event Bus 架构

```rust
/// 全局事件总线
pub struct EventBus {
    // 按事件类型分 Topic
    topics: HashMap<EventTopic, BroadcastSender<Event>>,
}

pub enum EventTopic {
    Agent,          // Agent 生命周期事件
    Tool,           // 工具调用事件
    Model,          // 模型调用事件
    Config,         // 配置变更事件
    Session,        // 会话事件
    File,           // 文件系统事件
    MCP,            // MCP Server 事件
    Plugin,         // 插件事件
    System,         // 系统事件
}

pub struct Event {
    pub id: String,
    pub topic: EventTopic,
    pub event_type: String,
    pub timestamp: i64,
    pub session_id: Option<String>,
    pub payload: Value,
    pub source: EventSource,
}

/// Event Bus 背压与持久化策略
///
/// 问题: 当 UI 消费速度 < Agent 事件产生速度时，事件堆积
/// 方案: 三级背压 + 持久化事件队列
pub struct EventBusConfig {
    /// 每 Topic 内存缓冲区大小 (默认 1024)
    pub buffer_size: usize,
    /// 背压策略
    pub backpressure: BackpressureStrategy,
    /// 是否持久化事件 (写入 SQLite event_queue 表)
    pub persist_events: bool,
    /// 持久化事件保留时间 (默认 7 天)
    pub event_retention_days: u32,
}

pub enum BackpressureStrategy {
    /// 丢弃最旧事件 (适合高频非关键事件, 如 progress)
    DropOldest,
    /// 丢弃最新事件 (适合状态快照, 如 AgentState)
    DropNewest,
    /// 阻塞生产者直到消费者追上 (适合关键事件, 如 tool_call_result)
    Block { timeout_ms: u64 },
}

impl EventBus {
    /// 发布事件，根据背压策略处理溢出
    pub async fn publish(&self, event: Event) -> Result<(), EventBusError> {
        // 1. 检查缓冲区
        let topic_state = self.get_topic_state(&event.topic);
        if topic_state.len() >= self.config.buffer_size {
            match self.config.backpressure {
                BackpressureStrategy::DropOldest => { topic_state.pop_front(); }
                BackpressureStrategy::DropNewest => { return Ok(()); /* 丢弃 */ }
                BackpressureStrategy::Block { timeout_ms } => {
                    // 等待消费者消费，超时后丢弃
                    tokio::time::timeout(
                        Duration::from_millis(timeout_ms),
                        topic_state.wait_for_space(),
                    ).await?;
                }
            }
        }
        // 2. 发布到 Broadcast Channel
        topic_state.push(event.clone());
        // 3. 持久化到 SQLite (异步，不阻塞)
        if self.config.persist_events {
            let db = self.db.clone();
            tokio::spawn(async move {
                db.insert_event(&event).await;
            });
        }
        Ok(())
    }
}

/// 事件持久化表 (用于崩溃恢复和审计)
/// CREATE TABLE event_queue (
///     id TEXT PRIMARY KEY,
///     topic TEXT NOT NULL,
///     event_type TEXT NOT NULL,
///     timestamp INTEGER NOT NULL,
///     session_id TEXT,
///     payload TEXT NOT NULL,   -- JSON
///     source TEXT NOT NULL,
///     consumed BOOLEAN DEFAULT 0,
///     created_at INTEGER NOT NULL DEFAULT (unixepoch())
/// );
/// CREATE INDEX idx_event_queue_topic_ts ON event_queue(topic, timestamp);
/// CREATE INDEX idx_event_queue_session ON event_queue(session_id);
///
/// 启动时重放未消费事件:
///   SELECT * FROM event_queue WHERE consumed = 0 ORDER BY timestamp;
```
